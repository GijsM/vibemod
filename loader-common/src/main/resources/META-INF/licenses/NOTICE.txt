The loader builds ship the libraries below inside the mod jar (Fabric:
META-INF/jars/, NeoForge: META-INF/jarjar/). None of them is relocated or
modified in any way; each nested jar is the unmodified artifact as published to
Maven Central.

Eclipse JDT Core Batch Compiler (ECJ)
  org.eclipse.jdt:ecj:3.42.0
  Eclipse Public License 2.0 (EPL-2.0)
  https://www.eclipse.org/jdt/core/  ·  https://www.eclipse.org/legal/epl-2.0/
  Full licence text: META-INF/licenses/ECJ-EPL-2.0.txt
  Eclipse's own about.html travels inside the nested ecj-3.42.0.jar.

  Why it is here: VibeMod compiles generated mods in-process. On a server or
  client launched with a JRE (or any runtime without javax.tools' system
  compiler) there is no javac to call, so ECJ is the compiler backend of last
  resort. See ARCHITECTURE-V2.md §7.3.

  Why it is here: Adventure is VibeMod's text currency across all three
  platforms. Paper provides it; the loaders do not, so it is bundled at exactly
  the version Paper ships, so the shared `core` classes run against the same
  bytes everywhere.

Not bundled, and deliberately so
  Gson — the game itself depends on it and both loaders put game libraries on
  the mod class loader, so a second copy would be a duplicate for no reason.
