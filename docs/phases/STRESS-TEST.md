# Stress campaign — hand-written limit-pushing mods through the real pipeline

Goal: act as the production LLM. Write ambitious native Fabric mods by hand, seed them the way the store does (`<gamedir>/vibemod/mods/<Name>/v1/*.java` + resources + `meta.json`, schema per the smoke scripts), and verify each mod compiles, survives the surgeon, hot-loads, and **actually does its thing** — asserted, not assumed. This is a discovery exercise: the deliverable is an honest per-mod verdict table plus any host gaps found. It is NOT a gate; do not wire it into `check`/CI.

## The two runs, and why neither is a gametest

The surface under test is **VibeMod's own running time**, so nothing here pre-bakes mods at boot. `smoke-fabric.sh` already gates restore-on-boot and `runClientGameTest` already gates a test-mode client with a seeded store; what has never been driven is a normal instance that has been up for a while, into which mods arrive one at a time.

**1. `scripts/stress-native.sh` — one continuous dedicated-server session (mandatory).** Boot the real installed jar with an **empty store**. Once it is up and ticking, seed each mod's files and hot-load it live with `vibe enable <Name>` over RCON — the product path: compile, surgeon, unfreeze window, `ReloadCoordinator`, live Brigadier install and the `SERVER_STARTED` replay all firing mid-session. Then observe behaviour over **real minutes on the clock**: MeteorStorm's ~600-tick cadence at least twice unaided, ArenaMaster's waves to completion, `time set night` and Nightmare's scaling on a spawned mob, and disable/enable/unload while the server keeps serving. One session, all mods, sequenced, with `T+<seconds>` on every step so "during running time" is evidenced rather than claimed.

**2. `scripts/stress-client.sh` — a real client, played.** Launch an ordinary client (`:fabric:runStressClient`, a Loom run config with `--quickPlaySingleplayer`) into a world, then drive it as a person at the keyboard would, via macOS `osascript` System Events: open chat with `t`, type `/vibe enable GrapplingHook`, Enter — the mod appears in the world you are standing in. Right-click the hook for real; send a real player chat line for ChatCraft; watch ZombieTitan's boss bar; see RubyEconomy's texture in your hand. Screenshots at each demonstrative moment. If macOS Accessibility blocks synthetic input, **stop that half and report the blocker verbatim** — do not fall back to a gametest and do not fake it. Run 1 stands alone.

The existing gate matrix (`./gradlew build`, `scripts/smoke-fabric.sh`, `scripts/smoke-neoforge.sh`, `:fabric:runClientGameTest`) must still be green at the end. Keep the mods in a `scripts/stress-mods/` tree; pattern-copy `smoke-fabric.sh`'s download/boot/RCON/assert plumbing.

Rules of the exercise:
- Write each mod the way a *good* LLM would from the current fabric profile prompt (read `PlatformProfiles.FABRIC` + few-shots first; use only what the prompt allows — no mixins, no reflection, no threads, ids get namespaced, dedicated server so no client classes, `Registry.register` allowed).
- javap anything you're unsure of before writing (the jars are at `~/.gradle/caches/fabric-loom/26.2/`). You're simulating a strong model, not a blind one — but record every place where you *needed* javap, because that's exactly where the real LLM will burn a repair round, and it's prompt-improvement signal.
- If a mod fails to compile/load: fix it like the self-heal loop would (record round count). If the failure is a HOST gap (surgeon too strict, seam missing, diagnostic unclear, teardown residue): record it verbatim; fix it only if small and obviously right, re-running `./gradlew build` + `scripts/smoke-fabric.sh` after any host change. Never weaken an assertion.
- For two mods, also round-trip `vibe disable` → assert behavior stops (where honestly assertable) → `enable` → assert it returns. Unload one registry mod and assert the ledger tombstones it.

## The roster (write all 8; ambitious but legal)

1. **GrapplingHook** — registered item (`Item` subclass, `use` override): raytrace up to 40 blocks (`player.pick` or manual `level.clip` — javap), launch the player along the vector (`setDeltaMovement` + `hurtMarked`/whatever 26.2 needs for velocity sync — javap), trail particles, 3s cooldown via `ItemStack` component or a UUID map. Assets: grid texture + item model + lang. Data: shaped recipe. RCON test: give via `/give`, verify registry id resolves, execute a fake use? (can't click over RCON — instead expose a `/grapple` command that calls the same code path on the console-targeted player... no player online on a smoke server; use the mod's own logic on a spawned armor stand or assert registration+recipe+component state instead, and mark "use-path untested headless" honestly).
2. **MeteorStorm** — every N ticks (~600) pick a random loaded player-ish location (no players → world spawn), spawn a falling-block "meteor" (`FallingBlockEntity` — javap the 26.2 spawn factory; it changed eras) with velocity, detect landing via per-tick scan of tracked entities, `level.explode` on impact, fire ring. `/meteor now` command forces one. RCON: run `/meteor now`, assert explosion logged/blocks changed (`execute if block` probes) and the tracked-entity cleanup on disable.
3. **ZombieTitan** — registered `EntityType<Zombie>`-based titan (vanilla `Zombie::new` factory through `EntityType.Builder`), default attributes ×5 health + SCALE 3 via attribute instance at spawn, `ServerBossEvent` boss bar while alive, custom loot via `data/` loot table + `onDeath` drop, `/titan spawn` command. RCON: spawn, assert entity exists (`execute if entity @e[type=vibemod_zombietitan:...]` — verify the type id shape), kill it, assert loot + boss bar cleanup.
4. **RubyEconomy** — currency chain: `data/` smelting recipe (redstone→ruby item), registered `ruby` item + `ruby_blade` (Properties.sword + attribute modifiers component), `/balance`/`/pay` commands with per-UUID balances persisted as JSON in the mod's data dir (plain `Files` IO — check what the policy allows for file IO; if `java/nio/file` writes are policy-limited, use the honest path and record it), balances survive disable/enable. RCON: recipe present, items registered, commands work from console with a fake-UUID arg form.
5. **ArenaMaster** — the Brigadier torture test: `/arena` tree with `create <name> <radius:int>`, `start <name> <waves:int>`, `stop`, `list`; literal + typed args (`IntegerArgumentType`, `StringArgumentType` — through the command seam), waves spawn escalating vanilla mobs on a ring, scoreboard objective tracks kills via entity-death event, `/arena stop` despawns by tag sweep. RCON: full tree exercised, suggestions? (skip), scoreboard asserted via `/scoreboard players get`.
6. **ChatCraft** — chat-driven crafting: `ALLOW_CHAT_MESSAGE`-era Fabric chat event (javap the exact 26.2 event — `ServerMessageEvents.ALLOW_CHAT_MESSAGE`) parses "craft me a <item>", gives the item if vanilla id exists, cancels the chat line; plus an mcfunction in `data/` invoked via `/function` as a bonus path. RCON can't chat as a player — assert the subscription exists (`vibe info`), the function path works, and mark chat-fire "needs a player" honestly.
7. **SkyGrid** — heavy world mutation: `/skygrid <radius:int>` builds a floating grid of varied blocks around 0,100,0 in ≤2k `setBlock`s per tick batches spread over ticks (self-rescheduling via tick event + counter — no scheduler API in native mods; this tests sustained per-tick work under the watchdog). RCON: run small radius, `execute if block` probes at grid points, assert no watchdog trip in the log for the batched version, then `/skygrid_greedy` variant that does it all in ONE tick to see what the watchdog does (expected: degrade path — record what actually happens, it must not kill the server).
8. **Nightmare** — the everything-mod: registered totem item + `data/` advancement granted on first join, damage event making nights harsher (ALLOW_DAMAGE scaling at night), lifecycle SERVER_STARTED replay (registers mid-session when seeded live via `vibe enable` — actually test the late-load replay), a `/nightmare` toggle command flipping a persisted flag, and an mcfunction ritual. This one gets the disable/enable round-trip AND the unload+ledger assert.

## Report

`docs/phases/STRESS-RESULT.md`: per-mod table (concept → compile rounds → surgeon verdict → loaded? → behaviors asserted (list) → honestly-untestable-headless items → verdict), noting for each that it was **loaded mid-session at T+Xs of a running instance** and what happened during that running time; host gaps found (with verbatim diagnostics); what the real LLM would likely get wrong (the javap-needed list); and the final transcript tails. A **live client run** section: per-mod what was done in-game, what was observed, screenshot paths, and any divergence from the headless verdicts — or the blocker, verbatim, if input automation was refused. If any host fix was made, list it + the re-run gate results. Then a short "what this proves / what it doesn't" paragraph.
